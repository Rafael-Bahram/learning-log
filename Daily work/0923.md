### 2.9 Comparison

- Greater / less than : a > b , a < b ;
- Greater / less than or equals : a >= b , a <= b ;
- Equals : a = b ;
-- Double equality sign "==" means the equality test  , while a sign equality sign "=" means an assignment.
- No equals : a != b .

2. String Comparison
- " Dictionary “ or " Lexicographical " is used to see whether a string is greater than another .
- Strings are compared letter-by-letter .
> - ```javascript
> - alert( "Z" > "A" ) ; //true
> - alert( "Glow" > "Glee" ) ; //true
> - alert( "Bee" > "Be" ) ; //true
> 1. The algorithm to compare two strings :
>> 1. Compare the first character of both strings ;
>> 2. If the first character from the first string is greater (or less) than the other string's, then the first string is greater (or less) than the second.
>> 3. Otherwise, if both strings' first characters are the same, compare the second characters the same way.
>> 4. Reapeat until the end of either string ;
>> 5. If both strings end at the same length, then they are equal. Otherwise, the longer string is greater.

4. Strict Quality
> Strict equality operator "===" checks the equality without type conversion.
>> Which is, if a and b are of different types, then a === b immediately returns false without an attempt to convert them.
> Strict non-equality operator "!==" .

5. Comparison with "null" and "undefined"
> ```javascript
> alert( null === undefined ) ; //false
> alert(null == undefined ) ; //true
> 1. null vs 0
> - ```javascript
> - alert( null > 0 ) ; // false
> - alert( null == 0 ) ; //false
> - alert( null >= 0 ) ; //true
>> - Comparisons convert null to a number, treating it as 0. That’s why ' null >= 0' is true and ' null > 0' is false.
>> - On the other hand, the equality check == for undefined and null is defined such that, without any conversions, they equal each other and don’t equal anything else. That’s why 'null == 0' is false.
> 2. undefined 
> - ```javascript
> - alert( undefined > 0 ) ; // false
> - alert( undefined == 0 ) ; //false
> - alert( undefined >= 0 ) ; //true
>> - Comparisons 'undefined > 0' and 'undefined < 0' return false because undefined gets converted to NaN and NaN is a special numeric value which returns false for all comparisons.
>> - The equality check 'undefined = 0' returns false because undefined only equals null, undefined, and no other value.

6. Avoid Problems
> Treat any comparison with undefined/null except the strict equality === with exceptional care.
> Don’t use comparisons >= > < <= with a variable which may be null/undefined, unless you’re really sure of what you’re doing. If a variable can have these values, check for them separately.
